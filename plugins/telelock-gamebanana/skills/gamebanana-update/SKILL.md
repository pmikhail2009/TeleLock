# Обновление Telelock на GameBanana

Карточка Telelock для Deadlock находится на https://gamebanana.com/mods/742883. Для публикации используй встроенный браузер Codex (`iab`) и открытую сессию GameBanana. При необходимости дай пользователю войти в этой вкладке.

При обновлении оставляй в опубликованном списке Files только актуальную сборку Telelock: новый VPK или ZIP с ним. Прежние VPK и архивы с прежними сборками удаляй после успешной публикации и проверки нового обновления. Это часть обычного обновления и не требует отдельного запроса. Локальные сборки и файлы другого назначения не удаляй. В режиме подготовки ZIP файлы на GameBanana не меняй.

1. Определи конкретную релизную сборку, версию и текст изменений из запроса и проверяемого контекста проекта. Сборка Telelock сохраняет `mod/build/<id>/package/pakNN_dir.vpk`. При нескольких подходящих файлах сверь их с результатом релизной сборки. Загружай только файл, выбранный для данного релиза.
2. Запусти PowerShell из корня проекта. Путь к скрипту вычисли относительно каталога этого навыка. Скрипт вернёт путь к ZIP, имя вложения и SHA-256 VPK. В режиме подготовки остановись после создания ZIP.

   ```powershell
   & '<skill-directory>/scripts/Prepare-GameBananaRelease.ps1' -VpkPath '<built-vpk>' -Version '<version>' -OutputDirectory 'dist/gamebanana'
   ```

3. Перед загрузкой сверь назначение, версию, содержимое обновления и выбранный файл с разрешением пользователя на этот релиз. Если запрос уже разрешает конкретную публикацию, продолжай. Проверь на https://gamebanana.com/mods/updates/742883, не опубликована ли эта версия. Если версия и файл уже совпадают, перейди к проверке и очистке на шагах 6–8 без повторной загрузки или создания Update. Если версия совпадает, а файл или текст расходятся, выясни у пользователя, какой результат нужен.
4. На странице мода открой **Edit → Media → Files**. Зафиксируй имена и доступные идентификаторы прежних VPK и архивов со сборками Telelock. В разделе Files выбери **Select files**. Следуй документации встроенного браузера по загрузке файлов. Зарегистрируй ожидание события `filechooser` до нажатия и передай абсолютный путь к подготовленному ZIP в `chooser.setFiles`. Дождись успешного завершения загрузки и нажми **Save**. Сохрани имя и доступный идентификатор, под которыми GameBanana показывает архив. Сайт может изменить регистр, разделители или добавить суффикс. Сверь присутствие архива в опубликованном списке файлов. До проверки нового обновления прежние файлы сохраняй.
5. Вернись в **Updates → Add Update**. Заполни **Version** и **Title**, если нужен отдельный заголовок. Добавь изменения через **Add Entry** или **Bulk Add**, задавая одну запись на строку через Bulk Add. Запятая в Bulk Add отделяет тип записи, поэтому записи с запятыми вводи через Add Entry. В секции **Files** отметь ровно тот архив, который был сохранён на предыдущем шаге. Включи **This update is significant** по запросу пользователя. Сверь поля и нажми **Save** в окне Add Update.
6. Проверь на странице Updates опубликованную версию, список изменений и ссылку на нужный архив. Убедись, что новый архив доступен для скачивания. Если публикация или доступность нового файла не подтверждены, прежние файлы не удаляй.
7. После успешной проверки вернись в **Edit → Media → Files**. Идентифицируй актуальный файл по сохранённому имени и идентификатору; при сомнениях сверь SHA-256 VPK внутри архива с результатом подготовки. Удали из списка Files все прежние VPK и ZIP со старыми сборками Telelock штатными действиями интерфейса, подтверди удаление, если сайт попросит, и сохрани изменения. Не ограничивайся снятием отметки у файла в Update или переносом в архив: прежних сборок не должно остаться в опубликованном списке Files. Не удаляй актуальный файл, записи Updates и файлы другого назначения. Если принадлежность файла к старой сборке неясна, останови удаление этого файла и сообщи об этом пользователю.
8. Повторно открой опубликованный список Files и страницу Updates. Убедись, что осталась ровно одна сборка Telelock — актуальная, её ссылка доступна, а обновление указывает на неё. Только после этой проверки считай обновление завершённым. Верни ссылку на обновление, если интерфейс её даёт, или ссылку на список обновлений с номером версии; сообщи, что прежние сборки удалены.

После ошибки на этапе сохранения сначала проверь страницу Updates и список Files. Если ZIP уже сохранён, используй существующую запись после идентификации файла по имени с хешем и, если принадлежность вызывает сомнения, по SHA-256 VPK внутри архива. Если ZIP появился, а Update отсутствует, продолжи с Add Update. Если сайт пока обрабатывает сохранение или результат неясен, проверь состояние перед повтором.

Если публикация уже проверена, но очистка прервалась, повторно проверь Files и продолжи удаление оставшихся прежних сборок. Не загружай новый дубликат и не создавай повторный Update. Если очистка не удалась, сохрани актуальный файл и явно сообщи, какие прежние файлы остались; не утверждай, что обновление полностью завершено.
