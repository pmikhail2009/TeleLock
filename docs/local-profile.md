# Локальный профиль Telelock

Меню восстанавливает последнюю привязку, язык, режим уведомлений и отображаемый уровень доступа из `telelock_profile_v1` в localStorage игрового Chromium. При повторном создании меню в той же сессии используется также копия на корневой панели Panorama. После загрузки страницы транспорта показ сохранённого профиля не ждёт HTTP-ответа.

Проверка связи и актуальности данных выполняется в фоне при обычном обновлении статуса. Сохранённая привязка и доступность сервера отображаются отдельно. Начальная загрузка HTTPS-страницы транспорта по-прежнему может требовать сеть; автономный холодный запуск не гарантируется.

Язык и режим уведомлений сначала записываются на ПК, затем отправляются на сервер. При сетевой ошибке последнее изменение каждого поля остаётся в локальной очереди, включая перезапуск игры. Следующий успешный статус запускает повторную синхронизацию. Подтверждение старого изменения не удаляет более новое. Запоздавший статус не перезаписывает уже синхронизированный локальный выбор. Ошибка записи на диск не выдаётся за успешное сохранение.

Профиль привязан к адресу шлюза и поколению привязки. Замена или удаление существующей привязки сбрасывает её ожидающие изменения. Конфликт поколения при сохранении вызывает повторную проверку статуса. Кэш уровня доступа используется только для интерфейса: права, подписка, срок действия и допустимость каждой операции по-прежнему проверяются сервером. Подписанные лицензии и автономная авторизация не вводились.

Cloudflare продолжает хранить привязки, настройки бота, доступ, команды и подтверждения; Telegram Serverless продолжает обрабатывать сообщения. Серверные схемы и службы менять не требуется. Локальные команды и результаты сохраняют существующее хранилище IndexedDB и механизм доставки.

Новый VPK запрашивает протокол панели с `profile=1`: промежуточные ответы `cached_linked`/`cached_unlinked` и признаки ожидающей синхронизации. Без этого параметра панель возвращает прежний формат, совместимый со старыми VPK. Для новой функции нужны обновлённые VPK и HTML-панель; публикация только одного из них не завершает обновление.

## Проверка

`node --test mod/*.test.mjs gateway/*.test.mjs`

`node --experimental-vm-modules --test serverless/test/*.test.mjs`

Сценарии локального профиля находятся в `mod/local-profile.test.mjs`: показ до HTTP-ответа, сохранение без сети и восстановление очереди после перезапуска, запоздавшие ответы, замена привязки, конфликт поколения, недоступный диск, повреждённый профиль и совместимость старого протокола. Эти проверки моделируют браузер и Panorama; реальная долговечность профиля CEF и поведение меню после перезапуска Deadlock требуют проверки в игре.

## Сборка и выпуск

Тестовая сборка с 22 ноября 2026 года находится в резерве и не входит в обычный комплект выпуска. Расположение сохранённых файлов и порядок возврата описаны в `docs/lab.md`. Дальнейшая разработка ведётся для обычного VPK; диагностический код сохранён.

Используется существующий `mod/build.ps1`: он компилирует ресурсы через Modlock и проверяет VPK через Source 2 Viewer. Для обычной сборки используется действующий URL панели, для тестовой — каталог `/lab/` и параметр `-Lab`.

При подготовке HTML нужно подставить действующий HTTPS-адрес Cloudflare в `meta[name="katka-gateway"]`. Домен страницы должен остаться прежним, иначе у Chromium будет другое origin-хранилище и прежний ключ установки не будет доступен. Панели обычной и тестовой версий могут использовать одно хранилище при одинаковых origin и адресе шлюза.

Публикация панели, установка VPK в игру и отправка Git-коммита в удалённый репозиторий выполняются отдельно от подготовки файлов.
