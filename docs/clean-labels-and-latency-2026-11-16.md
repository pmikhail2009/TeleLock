## Проверка задержки

Опубликованная панель использует
https://katka-game-gateway.pmikhail2009.workers.dev.
Пять последовательных POST /v1/status с отдельным тестовым ключом без
привязки вернули HTTP 200 за 504, 577, 47, 63 и 47 мс. Замеры сделаны
через Node fetch на этом ПК; они не воспроизводят CEF или доставку Telegram.
Windows proxy выключен; переменные HTTP_PROXY/HTTPS_PROXY/ALL_PROXY отсутствуют.
Проверка OPTIONS вернула HTTP 204, без Access-Control-Max-Age.
Загрузка панели GitHub Pages вернула HTTP 200 примерно за 1083 мс;
ответ шлюза на корневой путь (HTTP 404) — примерно за 1129 мс, включая TLS.
Эти два запроса проверяют доступность, а не время работы API.

Показатель «Отклик сервера» в игре измеряет performance.now() вокруг
fetch status и чтения JSON после получения ключа установки. Он включает
сетевой обмен, возможный CORS preflight и задержку исполнения в CEF,
но не всю доставку Telegram-команды. Обновление статуса каждые 12 с
не прибавляет автоматически 12 с к измерению. В контроллере есть
отдельный 10-секундный watchdog; это не формула показателя отклика.

Постоянная серверная задержка 11 с этими проверками не подтверждена.
Для локализации нужно сравнить отклик в активном меню игры и после
сворачивания, а также повторить сетевые замеры во время проблемы.
Возможные причины: CEF, сетевой маршрут/потери и серверная задержка,
которая отсутствовала в момент проверки. Конкретная причина не установлена.

Cloudflare сообщает об ограничениях трафика из РФ:
https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/.
Это возможный фактор, а не доказанная причина текущего случая.
Перенос панели и API на один HTTPS origin уменьшил бы число соединений
и убрал CORS preflight. Если замеры подтвердят проблему маршрута к
Cloudflare, можно рассматривать VPS с проверенным доступом из сети
пользователя и доступом к Telegram API. Перенос и публикация изменений
сервера в этой задаче не выполнялись.
